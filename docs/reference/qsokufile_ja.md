# qsokufile

*[English](qsokufile.md) | **日本語***

`qsokufile`は、リポジトリのコマンドの近道を持つ、1つだけのファイル。この文書はその書式の仕様を定める。`qsoku`コマンドライン自体については[cli_ja.md](cli_ja.md)を見ること。

## 置き場所と探し方

- ファイル名は必ず`qsokufile`（小文字）と一致させる。
- qsokuはカレントディレクトリから始めて親ディレクトリへ順にたどり、**最初に見つかった**`qsokufile`を使う。gitリポジトリの境界では止まらず、ファイルシステムのルートより上は探さない。
- 大文字・小文字を区別しないファイルシステム（macOS・Windows）では、`Qsokufile`や`QSOKUFILE`も見つかってしまう。作成・編集は常に`qsokufile`という名前で行うこと（`qsoku .init`は常にこの名前で書く）。マシンをまたいでも名前がそろう。
- `qsokufile`が見つからない場合、qsokuはエラーで終了し（終了コード1）、`qsoku .init`を案内する。

## 書式

- 1行が1つの項目：`名前: コマンド`。
- 行はまず前後の空白を取り除く。行の最初の`:`が名前とコマンドの区切りで、それより後ろを、先頭の空白を除いてコマンドとする。コマンド自身の内部の空白はそのまま保たれる。
- 行末の`\r`（CRLF改行）は解析前に取り除くので、Windowsで編集したファイルもそのまま読める。
- 空行（何もない、または空白だけ）は無視する。
- **コメント行**：行の最初の非空白文字が`#`であれば、その行はコメントとして無視する。`#`の前に空白があってもよい。行の途中や末尾にある`#`はqsokuにとって特別な意味を持たない（コマンドの末尾に書かれた`# …`は、`sh`に渡すコマンド文字列の一部としてそのまま渡り、`sh`自身がシェルのコメントとして解釈する）。
- 空行・コメント行でない行に`:`が無ければエラーで、qsokuはファイル名と行番号を示して終了する（終了コード1）。何も実行しない。
- 行の継続は無い。1つの項目は必ず1行。

## 名前

- 使える文字：英数字（ASCII）、`.`、`_`、`-`。
- 名前の**先頭**を`.`にしてはいけない（qsoku自身の管理用コマンドのために予約されている。`qsoku .init`・`qsoku .add`など。[cli_ja.md](cli_ja.md)を参照）。
- 名前の先頭を`-`に**してもよい**。qsokuは自分自身のコマンドラインオプションを持たない（`qsoku`の後の引数はすべて名前として調べられる）ので、区別すべき曖昧さが無い。
- 名前は大文字・小文字を区別する。
- 1つの`qsokufile`に同じ名前は1回までしか出せない。すでに定義済みの名前を2度目に定義する行はエラー（両方の行番号を示す。終了コード1）。`qsoku .add`はこの状況を作らない：すでにある名前を足そうとすると、その行を置き換える（[cli_ja.md](cli_ja.md)を参照）。

## `//`：qsokufileの置いてある場所

`//`は、使われている`qsokufile`が置いてあるディレクトリ（`QSOKU_ROOT`とも呼ぶ。[cli_ja.md](cli_ja.md)を参照）を表す。本物のルートパス`/`は`/`と書き、この規則の影響を受けない。

| 書き方 | 置き換えるか | 理由 |
|---|---|---|
| `cd //src` | する | コマンドの先頭＝単語の先頭 |
| `(cd //; make build)` | する | 単語の先頭：`(`の直後、`;`の後 |
| `foo \| cd //` | する | 単語の先頭：`\|`の直後 |
| `foo && cd //` | する | 単語の先頭：`&`の直後 |
| `curl http://example.com` | しない | `:`の後で、単語の先頭ではない |
| `grep "//" main.go` | しない | ダブルクォートの中 |
| `echo '//' is a comment` | しない | シングルクォートの中 |
| `build: (cd //; make build) # see //docs` | しない（`# see //docs`の部分） | その部分はコメント（上の「書式」参照）で、そもそも読まれない |

- **置き換える場所**：引用符の外で、単語の先頭にあるとき——コマンドの一番最初、または空白・`;`・`&`・`|`・`(`の直後。
- **置き換え方**：qsokuは、qsokufileの置いてあるディレクトリを環境変数`QSOKU_ROOT`として`sh`に渡し、一致する`//`を実行前に`"$QSOKU_ROOT"/`へ書き換える。置き場所のパスに空白があっても壊れない。
- **逃がし方**：`//`をそのまま使いたい（URLやコメントの中など）ときは、シングルクォートかダブルクォートでくくるか、コメントの中に書く——新しい記号は作らない。引用符の中でqsokufileの場所を使いたいときは、`$QSOKU_ROOT`を直接書く。
- **打たれた引数**：`qsoku cd //src`は、（利用者自身のシェルが引用符を取り除いた後の）`//src`を、`cd`の項目のコマンドへの引数として渡す。qsokuは同じ規則で置き換えるので、qsokufileのコマンドの中の`$1`は`/qsokufileのあるディレクトリの絶対パス/src`を受け取る。
- 実装上の注意：引用符の認識には、字句解析がシングルクォートの中・ダブルクォートの中・バックスラッシュの直後のどれにいるかを追うだけで足り、シェルの文法をすべて実装する必要はない。

## 例

```
root: cd //
cd: cd $1
build: (cd //; make build)
test: (cd //; go test "$@")

# フルクリーンビルド。
rebuild: (cd //; rm -rf dist; make build)
```
