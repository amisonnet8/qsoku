# qsoku 設計メモ

2026-09-22

## qsokuとは

qsokuは、**そのリポジトリ固有のコマンドセット**を`qsokufile`に書いておき、リポジトリのどこにいても`qsoku <名前>`で呼べるCLIツール。makeの`make build`から着想を得たが、依存関係やターゲットの仕組みは持たず、「短い名前 → コマンド」の対応表だけに徹する。

- シェルの`alias`との違い：`alias`は自分の環境全体に効き、リポジトリごとに変えられず、共有もできない。qsokuは`qsokufile`をコミットすれば、チーム全員が同じ近道を使える
- makeとの違い：makeはビルドの道具で、タブの決まりや`.PHONY`などの作法があり、`cd`のような移動は苦手。qsokuは近道の一覧に割り切り、`cd`も効く
- AIエージェントにも効く：`qsokufile`がそのリポジトリのコマンドの一覧になり、人間とAIが同じ名前で呼べる
- 独自の決まりは3つだけ（`qsokufile`の探し方、`//`、居場所の持ち帰り）。残りはすべて`sh`の知識で書ける
- 位置づけ：mtqgの段階2のサンプルPJ。本当に便利な道具になりそうなので、記録は使い捨てにせず残す方向

## 名前：qsoku

quick（速）と日本語の「速（そく）」を重ねた造語。打てばすぐにコマンドが走る道具だから。「キューソク」と読む。

`soku`は既存のCLIと衝突していたため避けた（Node.js製の Soku CLI、Go製で`soku init`を持つ soku CLI の2つがある）。`sok`は学術用語のSoK（Systematization of Knowledge）で検索が埋もれ、`skq`はPythonのライブラリが既にある。`qsoku`は検索した限り衝突がなく、造語なので検索もしやすい。

公開前に、GitHubやGoのパッケージで改めて同名がないか確かめる。

## qsokufile

設定ファイルは`qsokufile`の**1つだけ**。カレントから親へたどり、最初に見つかった`qsokufile`を使う。

```
root: cd //
cd: cd $1
build: (cd //; make build)
```

- 書式は`名前: コマンド`の1行。コマンドは`sh`の書き方で書く
- 名前は1つに決めた。認める名前が1つなら、「どれが使われるか」「複数あったらどうするか」という決まり自体が要らない
- 見える名前（隠しファイルにしない）：チームやAIが存在に気づけるように。`Makefile`・`Dockerfile`と同じ
- 小文字：コマンド名`qsoku`とそろえる。justの`justfile`が前例
- 名前は`.`で始めてはいけない（管理用コマンドのために予約）
- 探し方はgitやjustと同じ。サブディレクトリのどこからでも同じ`qsokufile`が使われる
- 注意：macOS・Windowsのファイルシステムは大文字・小文字を区別しないため、`Qsokufile`も見つかってしまう。`.init`は必ず`qsokufile`の名前で作り、名前をそろえる
- コメントは`#`から行末まで（シェル式）。空行は無視する
- `qsokufile`は**確認なしで実行する**。direnvはプロンプトのたびに自動で走るので許可制が要るが、qsokuは利用者が`qsoku`と打ったときだけ動くため

参考にした他のツールの決め方：makeは`GNUmakefile`→`makefile`→`Makefile`の順に探す。justは`justfile`（大文字・小文字を区別せず、`.justfile`も可）で親をたどる。Taskは`Taskfile.yml`、direnvは`.envrc`。独自の書式なら拡張子なしの「〜file」が定番。

## 実行：shで実行し、居場所を持ち帰る

コマンドは、どのシェルから呼ばれても**必ず`sh`で実行する**。実行が終わったときの居場所を持ち帰り、シェル連携がそこへ`cd`する。

```
root: cd //                           打った人も移動する
cd: cd $1                             打った人も移動する
build: (cd //; make build)            括弧の中の移動は外に出ない
test: (cd //; go test "$@")
run: (cd //; go run ./cmd/app ${1:-dev})
```

- **`cd`の問題**：qsokuは別プロセスなので、中で`cd`しても打った人のシェルの居場所は変わらない。zoxideやdirenvと同じく、シェル連携（`.bashrc`に1行書いてもらう方式）で解決する
- **括弧で区別する**：移動させたくないコマンドは`( )`でくくる。シェルのサブシェルの決まりをそのまま使い、新しい書き方を足さない
- **なぜ常に`sh`か**：`( )`がサブシェルになるのはbash・zsh・shの仲間だけ。fishでは出力の埋め込み、PowerShellではただのまとまりになる。リポジトリで共有するファイルなので、使う人のシェルで意味が変わらないよう`sh`に固定する
- シェル連携の部分は「最後の居場所に`cd`する」だけの数行で済むので、どのシェルにも用意しやすい
- **引数も`sh`の書き方**：`$1`、`"$@"`、`${1:-既定値}`など。qsokuは`sh -c 'コマンド' qsoku 引数…`と呼ぶだけで、引数の置き換えを自分では書かない。引用符の扱いも`sh`どおり

## `//`：qsokufileの場所

`//`は`qsokufile`の置いてある場所を表す。`/`は本物のルートのまま。`qsoku cd //src`のように、打つときの引数でも使える。

| 書き方 | 置き換えるか | 理由 |
| --- | --- | --- |
| `cd //src` | する | 単語の先頭 |
| `(cd //; make build)` | する | `(`と`;`の後の単語の先頭 |
| `curl http://example.com` | しない | `:`の後で単語の先頭ではない |
| `grep "//" main.go` | しない | 引用符の中 |
| `echo '//' is a comment` | しない | 引用符の中 |

- **置き換える場所**：引用符の外で、単語の先頭（コマンドの最初、空白・`;`・`&`・`|`・`(`の直後）にある`//`だけ
- **置き換え方**：`qsokufile`の場所を環境変数`QSOKU_ROOT`に入れて`sh`に渡し、`//`を`"$QSOKU_ROOT"/`に置き換える。場所のパスに空白があっても壊れない
- **逃がし方**：`//`をそのまま書きたいときは引用符でくくる。新しい記号を作らない。引用符の中で場所を使いたいときは`$QSOKU_ROOT`を直接書く
- **打たれた引数**：シェルが引用符を取り除いた後なので、`//`で始まる引数は置き換える
- 実装：引用符の状態（シングル・ダブル・バックスラッシュ）だけを追う小さな字句解析で足りる。URL、引用符の中、括弧の中、セミコロンの後をテストで押さえる

## 管理用コマンド（`.`で始まる）

管理用のコマンドは`.`で始める。`qsokufile`の名前は`.`で始めてはいけないので、利用者が`add`や`init`という名前を付けても絶対にぶつからない。予約語を覚えてもらう必要もない。

| コマンド | 内容 |
| --- | --- |
| `qsoku .init` | 今いる場所に空の`qsokufile`を作る |
| `qsoku .add root 'cd //'` | 名前とコマンドを追加する |
| `qsoku .rm root` | 名前を消す |
| `qsoku .list` | 登録されている名前とコマンドの一覧 |
| `qsoku .edit` | `qsokufile`を`$EDITOR`で開く |
| `qsoku .where` | 使われる`qsokufile`の場所（`//`が指す場所）を表示する |
| `qsoku .help` | 使い方と登録されている名前の一覧。引数なしの qsoku も同じ（git --help と同じイメージ） |

- `.add`・`.rm`が書き込む先は、親をたどって見つかった`qsokufile`。見つからなければ作らず、`.init`を案内する
- 同じ名前がすでにあるときの`.add`はエラー（黙って上書きしない）
- `.add`に渡したコマンドは書いたとおりの文字列で保存する。`//`は実行するときに初めて置き換える。シングルクォートでくくって渡してもらう
- 書き換えは最小限：`.add`は末尾に1行足す、`.rm`はその1行だけ消す。手で書いたコメントや並び順を崩さない
- 引数なしで`qsoku`と打ったときは`.help`と同じものを出す

## 実装とシェル連携

**Goのバイナリで作る。** シェル関数だけでも作れる規模だが、`//`の置き換えは引用符の状態を1文字ずつ追う処理で、シェルでは書きにくく遅く、対応するシェルの数だけ書き直すことになる。`qsokufile`はチームやAIと共有するものなので、**利用者の環境によらず同じ動きをする**ことが大事。解釈は1か所（バイナリ）に集める。mtqgと同じく、純粋なGo（cgoなし）、配布は最初`go install`。

シェル側は、**居場所を持ち帰って`cd`する数行だけ**。`.bashrc`などに1行書いてもらう。

```
eval "$(qsoku .shell bash)"
```

これが展開する関数（bash・zsh）：

```
qsoku() {
  local f; f=$(mktemp)
  QSOKU_CWD_FILE=$f command qsoku "$@"
  local status=$?
  local dir; dir=$(cat "$f"); rm -f "$f"
  [ -n "$dir" ] && [ "$dir" != "$PWD" ] && cd "$dir"
  return $status
}
```

**居場所の受け渡し（決定）**

qsokuは、`sh`に渡すコマンドの末尾に、居場所を書き出す1行を**改行で**足す。

```
sh -c '<qsokufileのコマンド>
__status=$?; pwd > "$QSOKU_CWD_FILE"; exit $__status' qsoku "$@"
```

- 別プロセスのqsokuからは、`sh`が最後にどこにいたかを知る方法がないので、`sh`自身に書き出させる
- **改行でつなぐ**（`;`ではなく）。コマンドの末尾にコメント（`# …`）があると、`;`で足した部分までコメントに飲まれる
- 変数名は`__status`のように、利用者のコマンドとぶつかりにくいものにする
- **成功でも失敗でも持ち帰る。** 分岐を作らない
  - `qsoku cd //src`が失敗した場合（そのディレクトリがない）は`pwd`が変わっていないので、持ち帰っても移動は起きない
  - `(cd //; make build)`は括弧の中なので、成否に関わらず居場所は変わらない
  - `cd //src && make build`のように括弧なしで書いてビルドが失敗した場合は、そこまで進んだ居場所を持ち帰る。利用者が括弧を付けずに書いた以上「移動もしてほしい」という意図であり、失敗した場所にいるほうが直しやすい
- qsoku自身のエラー（`qsokufile`に名前がない、`sh`が起動できない）では一時ファイルに何も書かれない。シェル関数は「空なら`cd`しない」ので、そのまま何も起きない

- **一時ファイルで受け渡す**：zoxideやdirenvは「シェルのコードを出力して`eval`させる」方式だが、qsokuは実行したコマンド自身の出力（`make build`のログなど）が標準出力に流れるので混ぜられない。環境変数`QSOKU_CWD_FILE`で一時ファイルの場所を渡し、qsokuが終了時の居場所をそこに書く。コマンドの出力は素通しで、パイプもリダイレクトもそのまま使える
- **名前は`.shell`**（`.init`は`qsokufile`を作るほうに使うため）。zoxideの`zoxide init bash`と同じく、シェル名を引数に取る
- **関数名は`qsoku`のまま**。zoxideの`z`のような1文字にはしない。`s`は利用者の`alias`とぶつかりやすく、`qsoku`は元々4文字。短くしたい人は自分で`alias s=qsoku`と書けばよい。`command qsoku`で関数自身を呼ばないようにする
- 対応するシェルは**bash・zsh**（同じ関数が使える）と**fish**（書き方が違うだけ）。**PowerShellは対象外**（qsokuは`sh`で実行するので、WindowsではGit BashやWSLが要る）
- READMEには、シェルごとに「どのファイルに何を書くか」の表を必ず載せる（direnv・zoxideと同じ）
- 近いツール：zoxide（`eval "$(zoxide init bash)"`で`z`関数を定義し、打ったときだけ動く）が一番近い。direnvは形は同じだが、プロンプトのたびに自動で走るフック。Oh My Zshはzshの設定の枠組みで、別物
- **シェル補完をやる**（登録されている名前を補完する）。対応するシェルは連携と同じ
- **終了コードは`sh`のものをそのまま返す。** makeは自分の決まり（レシピが失敗すると、レシピの終了コードではなくmake自身の`2`）を返すが、qsokuは薄いラッパーなのでそのまま通す。`qsoku test`をCIでそのまま使える

## GitHubの看板

**Description**

> qsoku - Per-repository command shortcuts. Write `name: command` in a qsokufile and run it from anywhere in the repo, including `cd`.

何をするか、どう書くか、makeとの違い（どこからでも打てる、`cd`も効く）が1行に入る形にした。中身が変わっても古くなりにくい。

候補に挙げて外したもの：共有を前に出す案（「Commit a qsokufile, and everyone (and every AI agent) runs the same commands by the same names.」＝価値は伝わるが、何をするツールかが後回し）、makeとの対比で始める案（＝速く伝わるが、ビルドの道具と誤解されうる）。

**Topics**

- 今付ける：`cli`、`go`、`shell`、`bash`、`zsh`、`fish`、`developer-tools`、`productivity`、`shortcuts`、`command-runner`、`task-runner`、`dotfiles`
- `command-runner`・`task-runner`は、justやTaskを探している人の入口になる
- `ai-agents`は、AIエージェント向けの機能や説明が実際にできてから足す（まだない機能のTopicsを先に付けない）

**README**

- mtqgと同じく、**READMEは最後に作る**（リポジトリの看板なので、作りながら見えてきた魅力を完成に近い段階で打ち出す）
- 英語版（`README.md`）と日本語版（`README_ja.md`）を同時に作り、見出しのすぐ下に相互リンクを置く
- シェルごとに「どのファイルに何を書くか」の表を必ず載せる（direnv・zoxideと同じ）
