# qsoku 設計文書

qsokuの設計判断と、その理由の記録。日本語のみ（英語版は作らない）。

## 位置づけ

- ここにあるのは「**なぜこうなっているか**」の記録。**現在の仕様（何をするか）は`docs/reference/`が正**であり、食い違う場合はreferenceに従う
- 設計判断を変えるときは、まず`docs/reference/`を更新する。ここには今の設計と、前のやり方に戻すと同じ問題が起きる判断の理由だけを書く。それ以外の経緯（日付ごとの流れ、途中の履歴）はmtqgに記録する（`.claude/rules/documentation.md`）
- 進捗・現在地・保留事項はここには置かない。mtqgのtodo・memoにある（`CLAUDE.md`「記録の使い分け」）

## ファイル

| ファイル | 中身 |
|---|---|
| `note.md` | 最初の設計メモ（2026-09-22、原文から役目を終えた節——「GitHubの看板」「未決事項」——だけを除いたもの）。qsokuとは何か、名前の由来、`qsokufile`の書式、実行方式（`sh`固定・居場所の持ち帰り）、`//`の置き換え規則、管理用コマンド、実装方針 |

`note.md`は原文保存が基本方針だが、後の判断で明確に覆り、事実と異なってしまった記述（例：PowerShellを対象外としていた箇所、2026-09-27に方針を改めた）は、そのまま残すと誤解を招くため直接書き換えている。判断が変わった経緯自体はmtqgの記録にある。
